# アスレチック人狼

オンライン対戦型・3Dアスレチック人狼ゲーム。プレイヤー全員で足場を配置してコースを作り、投票で選ばれたプレイヤーは脱落し、騎士の守護と人狼の破壊を経て、最後は3Dアスレチックで村人陣営がゴールを目指します。

## 起動方法

```bash
npm install
npm start
```

起動後、ブラウザで **http://localhost:3000** を開いてください（ポートは環境変数 `PORT` で変更可。デフォルト 3000）。
同じネットワーク内の他の端末からは `http://<サーバーのIP>:3000` で参加できます。

## 遊び方（ゲームの流れ）

1. **ロビー**：「参加する」でエントリー（上限10人）。ホスト（最初の接続者）が3人以上のエントリーで「ゲーム開始」を押せます。ホストは「ルール設定」で騎士・狂人・人狼の人数、「アスレチック制限時間」（1〜10分のスライダー、初期値5分）、「BOT人数」（初期値0人、決定するとロビーのBOT数がその人数になるよう増減します）、「倍率ゲージ」（ONにすると溜めジャンプの溜め中に倍率ゲージが表示されます。初期設定はOFF）、「溜めジャンプ力」（4〜5秒溜めて発動した溜めジャンプの飛行中の水平移動速度に掛かる係数。初期値1.0倍・最小0.5倍・最大3.0倍・0.1倍刻み）を変更できます（人数別範囲・人狼陣営は半数未満をサーバーでも検証。新規2項目もホストのみ変更でき、再戦後も引き継がれます）。入室時の初期プレイヤー名は、既存プレイヤーと重複しないようサーバーが自動で一意化します（後から設定で変更した名前は対象外）。
2. **役職通知**：自分の役職を確認します。人狼同士だけが互いを把握できます。
3. **配置フェーズ**：ランダムな先手から時計回りに、手札のカードを1手番1個まで配置（合計10個）。全員がパスした後はパス不可になります。自分の手番の間は画面枠・バナー・自分の情報エリアが発光して強調されます。脱落したプレイヤーの手番はスキップされます。
4. **投票（脱落方式）**：配置フェーズ中、自分の手番に「投票」ボタンを押すと投票イベントを発生させられます（1人1ゲーム1回まで、使用後はグレーアウト。手番は消費しません）。また、足場が合計10個に到達したときも自動で投票が発生します。投票では全ての未脱落プレイヤーが、対象を1人だけ選ぶか、誰にも投票せずパスできます（1人1票制。投票先・得票数は非公開、「投票する」を押した後はサーバー側でも変更不可）。最多得票者が1人だけで、かつその得票数が生存（未脱落）プレイヤー数の過半数を超えている場合に、その1人だけが**即座に脱落**します（1回の投票で脱落するのは最大1人）。最多票でも過半数以下の場合や同点トップの場合は脱落者は出ず、その旨（「投票の結果、脱落者はいませんでした」）が全員に通知されます。投票中は投票先は非公開ですが、**結果発表のタイミングで投票対応が全員に開示**されます。表示形式は投票先ごとのグルーピングで、各行は「［投票先のカラードット＋名前］または［パス］：［その投票先を選んだ投票者たちのカラードット列］」です（**投票者は名前を出さずカラーのみ**で表示。結果パネルに見出しとして脱落者名、または「脱落者はいませんでした」を表示し、通常は8秒で閉じます。ただし投票結果の直後にアスレチックフェーズへ入るケースでは表示が4秒に短縮されます）。投票結果の通知はこの結果パネルに一本化されており、投票結果のトースト（脱落／脱落なし）は表示されません（守護・破壊など他のトーストは従来どおり）。手番中の投票イベント・10個到達時の最終投票の両方が対象です。脱落したプレイヤーの足場はすべて粉砕アニメーション付きで破壊され、カードに戻ってそのプレイヤーの手札と合算され、他の未脱落プレイヤー全員へ均等寄り（偏り最大1枚差）に再配分されます。設置数は破壊分だけ減り、10個未満なら配置フェーズが続きます（10個に戻れば再び投票が発生します）。誰が脱落したかは結果パネルで全員に通知されます。配置フェーズで村人陣営が0人になったら、その時点で人狼陣営の勝利でゲーム終了します（人狼陣営が0人になってもゲームは続行し、人狼役職が0人の場合は破壊イベントをスキップします）。また、配置フェーズ中に切断（＝脱落扱い）などの影響で村人陣営の参加者が全員ゴースト状態になった場合も、その時点で人狼陣営の勝利で終了します（判定は切断・再接続・投票集計・配置開始の各タイミングで現在の状態に対して行います）。観戦者は投票パネルを見ることはできますが、対象ボタン・「投票する」・「パス」はすべてグレーアウトされ、投票には参加できません（サーバー側でも観戦者の投票は受理されません）。
5. **守護・破壊**：騎士が秘密裏に守る足場を1つずつ選択 → 人狼の担当1人が破壊対象を1つ選択。守られていれば破壊は無効です。足場は3Dマップ上を直接クリックして選べます（竹輪はどのパーツでも選択可）。自陣UIの足場ボタンや3D画面の足場にマウスを合わせると、その3D足場が発光パルスで強調されます。破壊された足場は破片が飛散して落下しながら消える粉砕アニメーションで消えます。
6. **アスレチック**：制限時間はルール設定に従います。開始前に、直前の投票で脱落したプレイヤー（いる場合のみ）を画面中央で発表し、その後3秒カウントダウン（カウントダウン中もマウス/パッドで視点操作可）。順序は常に「投票結果パネル → パネルが閉じる → 脱落者発表 → カウントダウン → GO」です：直近の投票結果パネル（通常は表示8秒）がまだ表示中のタイミングでアスレチック開始になる場合は、そのケースに限ってパネルの表示を4秒に短縮したうえで、パネルと発表・カウントダウンが重ならないよう、サーバー側で発表開始時刻（presentAt）を「投票結果時刻＋4秒」にし、GO時刻（goAt）もその分後ろ倒しにします（goAt = presentAt + 4700ms）。パネルの表示終了時刻はサーバー時刻で一元管理され、短縮は表示中のパネルにも全クライアント共通で適用されます。投票結果から十分に時間が経っている通常ケース（守護・破壊に時間がかかった場合など）では遅延は入りません。発表・カウントダウンはサーバー時刻ベースで進むため、タブが非アクティブだった場合は復帰した時点で正しい状態（発表終了・現在のカウント・GO済みなら即操作可能）に即座に同期します。村人陣営の生存者が1人でもゴール島に着地すれば村人勝利。全村人脱落か時間切れで人狼勝利。落下するとゴースト（半透明・攻撃不可・生存者からは見えない）になります。
7. **リザルト**：役職と脱落状況を公開。「再戦」は参加中で、「退出」は未エントリーでロビーに戻ります。

### 1人で試す場合

ホストの「ルール設定」で「BOT人数」を2人以上に設定し（決定するとロビーにBOTが増減します）、エントリーして開始してください。BOTは配置・投票（投票イベントの発生・投票・パス）・守護/破壊を自動で行い、アスレチックでは配置された足場の上面を順にたどって（到達可能な足場へ歩行・ジャンプで）ゴールを目指します。たどれない場合は落下して脱落し、人間と同じくゴースト化します。BOTにホスト権が移譲されることはありません。試合が終わるとBOTは自動で再エントリーします（人間は「再戦」/「退出」の操作が必要です）。BOT人数の設定は再戦後も引き継がれます。

### 複数タブで遊ぶ場合

同じブラウザの複数タブでも、それぞれ別のプレイヤーとして参加できます（セッションはタブ単位で保持され、同じタブのリロードでは同じプレイヤーとして再接続します）。

| 操作 | キーボード・マウス | PS4コントローラー |
|---|---|---|
| 移動 | WASD（キーコンフィグで変更可） | 左スティック |
| 視点 | 右ドラッグ（設定でFPS式マウス視点に変更可） | 右スティック |
| ジャンプ | Space（押した瞬間のみ） | △（キーコンフィグで変更可） |
| パンチ | **Shift**（初期設定。キーコンフィグで他のキー/ボタンにも変更可。モーション完了まで再パンチ不可） | □（キーコンフィグで変更可） |
| 溜めジャンプ | **左クリック長押し→離して発動**（キーコンフィグで変更可。下記「溜めジャンプ」参照） | **×**（キーコンフィグで変更可） |
| ズーム | マウスホイール | L1＋右スティック |

- 配置フェーズ：カードをクリックで選択 → 3D画面を左クリックで「仮配置」（位置と角度は固定され、もう動かない）→ もう一度左クリックで**確認ダイアログ（「配置を確定しますか？　はい／いいえ」）**が開き、**「はい」で配置確定**（サーバーへは確定時に1回だけ送信）。**「いいえ」を選ぶと仮配置のまま戻ります**（キャンセルではありません。再度クリックすればまたダイアログが開きます）。水平移動・テレポは1クリック目で始点、2クリック目で終点、3クリック目で確認ダイアログ。細長は仮配置後、バーへのマウスダウン＋ドラッグで「掴んで回す」感覚で向きを直接操作でき（何度でもやり直し可）、ほとんど動かさないマウスアップ（クリック）で確認ダイアログが開きます。ダイアログ表示中は背後のキャンバス操作を受け付けません。ホイールは細長の仮配置中はバーのねじり、観覧車のプレビュー中は回転位相の調整、それ以外の場合はカメラズームです。右クリックでいつでもキャンセルできます（右クリックではダイアログは出ません）。観覧車は仮配置中も回転モーションをプレビューできます。**観覧車のプレビュー中（ゴースト表示中〜配置確定前）は、マウスホイールで回転の周期（位相）を進めたり戻したりできます**：ホイールを奥へ回すと位相が進み、手前へ回すと戻ります。1ノッチで周期の1/12（30°）ずつ動き、トラックパッドの小さな連続スクロールは蓄積されてノッチ換算されます。この間はカメラズームより位相調整が優先されます。**プレビューで見えていた位相はそのまま配置に引き継がれます**：位相は「サーバー時刻ベースの共通周期関数＋配置時に保存される位相オフセット」でプレビュー・配置後の実体・サーバーの支持判定すべてが同じ計算をするため、確定の瞬間にゴンドラの位置がズレることはありません。高さは下部のスライダー（0.5刻み）、または横の数値入力欄への直接入力（**0.1刻み**）で調整できます。**配置に使う高さは数値入力の 0.1刻みの値が正**です：数値を 0.1 単位で入力すると、スライダー表示は最も近い位置に寄るだけで、数値が 0.5 刻みに丸められて上書きされることはありません。スライダーを動かした場合は、従来どおり 0.5刻みの値が数値欄に反映されます。範囲は 0.5〜16 にクランプされます。配置カメラは右ドラッグで回転、ホイールでズーム（細長の仮配置中・観覧車のプレビュー中を除く）。
- 設定（⚙）から、名前変更、上下反転、3D酔い防止モード（初期ON）、マウス設定が変更でき、値はブラウザに保存されます。キーコンフィグではキーボード・マウスに加えてPS4コントローラーのボタン割当と左/右スティック入れ替えも設定できます。ホストは設定からゲームを強制終了できます。
- アスレチック中は各プレイヤーの頭上にカラードット＋名前のネームプレートが表示されます（ゴーストは生存者には名前ごと見えません）。キャラクターは手足つきで、歩行・待機・パンチのモーションが同期します（パンチは振りかぶり→突き出し→戻りの3段階）。歩行モーションは自分の移動入力に対する速度でのみ再生され、移動する足場に運ばれているだけでは再生されません。キャラクターは移動中は進行方向を向き、停止してもその向きを保持します。
- 生存プレイヤー同士はすり抜けず、接触すると押し合います（ゴーストとは衝突しません）。パンチの当たり判定は前方1.35m・左右±60°以内のみで、真横・背後・遠距離には当たりません。命中時の水平ノックバックは3.2m（従来の2倍）で、垂直方向への吹き飛ばしはありません。テレポの瞬間移動では乗っているプレイヤーは運ばれず、取り残されて落下します。ブラウザが非アクティブで位置申告が途絶えたプレイヤーは、サーバーが物理（ノックバック・足場判定・重力・脱落）を代行して権威位置を確定します。

### 溜めジャンプ（アスレチック中のアクション）

- **操作**：初期設定はキーボード/マウス＝**左クリック（Mouse0）**、PS4コントローラー＝**×（Pad0）**。どちらもキーコンフィグで変更できます。これに伴い**パンチの初期設定は Mouse0 から Shift に変更**されました（Shift は修飾キー単独バインドとして扱われ、発火は押下エッジ）。保存済みのキーコンフィグ（localStorage）は無理に書き換えません：新しい初期設定は「未設定のアクションへの補完」と「リセット時」にだけ適用されます。
- **溜め**：対応キー/ボタンを押し続けると溜めポーズに入ります。**ポーズは溜め時間では変化しません（固定ポーズ）**：脚は折り曲げず通常の立ち姿勢で、**右腕は肘を曲げて前へ、左腕は肘を曲げたまま後ろへ引いた**姿勢です。歩きながらも溜められ、その場合は脚は歩行モーションを継続し、腕だけこのポーズを歩行モーションに重ねます。溜め中の倍率ゲージは、ルール設定「倍率ゲージ」がONのときだけ本人の画面に表示されます（溜め進捗バー＋現在の倍率表示、4秒以降は赤表示。初期設定はOFF）。
- **開始条件**：溜めを開始できるのは「接地していて、他のアクション（パンチ・通常ジャンプ・溜めジャンプの跳躍中）を実行中でなく、**その瞬間に新たに押した（押し直した）入力**」だけです。**押しっぱなしの持ち越しは一切しません**：使用不可の間に押し始めた入力、フェーズ開始/終了・リスポーン・カウントダウンをまたいで押し続けている入力では溜めは始まらず、いったん離して押し直す必要があります（ポインターロック取得のためのクリックの長押しでも始まりません）。
- **発動**：ホールドを離した時点で発動します。または溜め開始から **5秒** 経過した時点で自動発動します。**跳躍時間は溜め時間（倍率）に関わらず常に 0.3秒** です。ここでいう跳躍時間とは「跳躍し始めた足場から跳躍の頂点に達し、跳躍し始めた足場の高さに戻るまで」の時間で、上昇 0.15秒＋下降 0.15秒です。頂点の高さ H = 通常ジャンプの頂点高さ × 倍率 とし、垂直初速 v0 = 2H/0.15、跳躍中の重力 g = v0/0.15 で決まります（`public/js/charge.js` の `leapParams`。跳躍中はこの重力で速度Verlet積分するため、頂点高さと往復時間が設計値どおりになります）。跳躍モーション（専用ポーズ）の時間も 0.3秒です。
- **跳躍中**：着地するまで、他のアクション（パンチ・通常ジャンプ・再度の溜め）は実行できません。水平方向は、**その瞬間の移動キー入力の方向（カメラ相対）に「通常の空中移動速度 × 倍率」の速さで進みます**。キー入力がなければ水平速度は 0（垂直に上昇・下降するだけ）で、入力方向が変われば空中でも即座にその方向へ転換し、入力をやめた間は水平に進みません（例：無入力で跳躍→空中で前入力→前に進む→右入力→右へ転換）。**ルール設定「溜めジャンプ力」**：溜め時間 t が 4 < t < 5 の手動リリース発動の飛行では、上記の水平速度にルールの係数（0.5〜3.0倍）がさらに掛かります（`public/js/charge.js` の `leapHSpeedFactor`。発動時点のルール値で確定し、飛行中の変更は効きません）。t=4ちょうども含む 0〜4秒溜めの飛行と、5秒自動発動の飛行には適用されず、垂直方向の跳躍力・滞空時間にも影響しません。足場に着地できず奈落へ落ちる場合は、跳躍中の重力・速度のまま落下し続けます（落下し始めても通常の落下へは切り替わりません）。
- **キャンセル**：溜め中に歩いて足場から離れる等で空中に出た場合、溜めはキャンセルされます（発動しません）。
- **倍率カーブ**（直線・一次関数。倍率は頂点の高さ（跳躍力）と、跳躍中の水平移動速度の両方に掛かります。通常ジャンプ＝倍率1.0。定義は `public/js/charge.js` の `chargeMultiplier`）：
  - 溜め時間 t が 0〜4秒：`倍率 = t/4`（t=0 で 0、t=2 で 0.5、t=4 で 1.0＝通常ジャンプと同程度）
  - t が 4〜5秒：`倍率 = 1 + 9 × (t-4)`（t=4.5 で 5.5、t=5 直前で約 10 へ直線的に上昇）
  - **5秒での自動発動：倍率は 1.0**（満タンまで溜めたのに自動発動すると通常ジャンプ程度に戻る、というリスク設計）
- **マルチ同期**：溜め中であること（開始/キャンセル）と発動（倍率）は他クライアントにも送信され、他プレイヤーのキャラにも溜めポーズ/跳躍ポーズが見えます。サーバーの物理代行（非アクティブプレイヤー）では溜めジャンプを再現しません（対象外）。BOT は溜めジャンプを使いません。

## 足場の種類

安定（立方体）／浮島（安定の4倍面積）／竹輪（上面の面積は安定と同じで全面に乗れる。空洞は側面中央の見た目だけのトンネル。生存者が乗って2秒後に微振動→落下し、復活を繰り返す）／水平移動（4秒移動→2秒停止→4秒で戻る→2秒停止の12秒サイクル）／観覧車（縦の円軌道）／細長（棒状・全方向に360°回転可）／テレポ（2地点を3秒周期で瞬間移動、直前1秒は消失アニメ）

## 変更履歴（2026-11-10 質問2件の切り分けと不具合2件の修正）

- **項目1（2人以下で範囲外の役職設定が警告されずに決定できる）**: 第17ラウンド修正9の副作用では**ありません**。修正9が変えたのは検証に使う人数の出所（BOT変更前のエントリー数 → BOT適用後の人数）だけで、「実効人数が3未満なら検証エラー自体を捨てる」緩和はクライアント（`if (n >= 3)` でチェック全体を包む）とサーバー（`if (err && nAfter >= 3)` ＋「3未満のときは緩く保持し、開始時に再検証する」のコメント）の両方に修正9以前から存在しました。BOT変更を伴わないケースでは修正9の前後でこの挙動は同一です。ユーザーの要望どおり、表示されている3人用の範囲に合わせて、2人以下でも3人基準で警告・検証するよう変更しました（サーバーは `validateRules(Math.max(nAfter, 3), next)` の結果を常時適用、クライアントも検証人数を最低3人にして合計・陣営上限・範囲のチェックを常時実行）。修正9の「BOT適用後の人数で検証」は維持（2人＋BOT5=7人なら人狼2が同一 rule:set で受理されることを回帰テスト S12 で確認）。game:start 時の再検証は従来どおり残っています。
- **項目2（傾けた細長の判定が見た目と一致しない）**: 第17ラウンド修正7の副作用では**ありません**。修正7が触った `rotAABBHalf` は配置制限専用で、支持判定の経路（クライアント `collideLong`/`longTopAtCollider`、サーバー `obbTopAt`＝BOT・サーバー物理代行が使用）からは一切使われておらず、支持側は修正7以前からクライアントと同じ Rx·Ry·Rz の行列を使っていました。ただし症状自体は**実在**し、原因は支持上面Yの計算式でした。旧式は「足元XZのローカル座標における上面点の高さ」を返しており、傾いた足場ではその上面点のワールドXZが足元XZとずれるため、見た目の上面と判定が食い違っていました（実測: 無回転・ヨーのみではずれ 0、ロール 0.30rad で最大 0.087m、ロール 0.60rad で最大 0.51m、複合回転 (0.61, 0.73, 0.24) で最大 0.89m。THREE の実ジオメトリへのレイキャストでも、見た目の上面は平面厳密式と 0.00000m で一致し、旧式とは最大 0.89m ずれることを独立に確認）。サーバーの `obbTopAt` とクライアントの `longTopAtCollider`/`longTopAtClient` を「上面平面と足元XZの鉛直線の交点Y」を返す厳密式に置き換え（フットプリント判定は交点のローカル座標で行う）。修正後は全ケースで最大ずれ **0.0000m**（回帰テスト S15 でも 645 点比較で 0）。
- **項目3（最終投票の最後の1票が離脱で確定すると足場が破壊されない）**: ユーザー提示のとおり `handleParticipantDrop` の処理順が原因でした。回収（`applyEliminationCleanup`）を投票の完了判定より前に実行するよう順序を入れ替えました。副作用の精査: (1) 手番投票の途中の離脱でも回収→投票解決の順で正しく働く。(2) 投票で別人が脱落した場合の回収は `resolveVoteSession` が自分の対象にだけ行うため二重にならない（離脱者は解決時点で脱落済み＝集計対象外）。(3) 最終投票では回収で設置数が減った状態を解決側が判定するため、設置数不足なら守護へ進まず配置が再開される（投票完了より前に離脱した従来ケースと同じ結果に揃った）。回帰テスト S13 はユーザーの再現手順そのまま（3人・10個配置・最終投票で2人が投票後に最後の1人が切断）で、離脱者の足場 3 個が回収され（10→7）、手札が再配分され（カード総数 15 で保存）、手番が生存者へ移ることを確認。対照ケース（投票完了前の離脱）も従来どおり回収されることをあわせて確認。

## 変更履歴（2026-11-09 多項目対応）

- **プレイヤーIDの分離（セキュリティ）**: 内部ID（sessionId）は本人のプライベート情報としてのみ返し、公開状態・各種イベントで使うIDは別途発行するランダムな公開IDに統一しました。他人の公開IDを提示しても席は奪えません。守護/破壊の担当者IDは公開状態に含めず、担当本人へはプライベート経由（isGuardTurn / isDestroyer）でのみ伝えます。
- **不正・欠落パケット耐性**: 全ソケットハンドラを例外ラッパーで包み、引数なし・型違いのパケットはそのイベントだけを無効化して処理を続けます。プロセス全体が落ちて全員が切断されることはありません（ファズテストで検証）。
- **切断脱落の後処理**: 配置フェーズで切断して脱落したプレイヤーにも、投票脱落と同じ処理（足場の全破壊→カード化→手札と合算→他の生存者へ再配分）を行い、設置総数が減った状態で配置を継続します。守護/破壊/アスレチック中の脱落は、カード再配分に意味がなく足場破壊が破壊フェーズの仕組みと競合するため、脱落扱いのみです。
- **守護・破壊フェーズの村人全滅検出**: 守護/破壊中に生存村人が全員切断した場合も、その時点で人狼勝利として終了します（以前はアスレチックが始まって制限時間まで待たされました）。アスレチック開始直後にも同じ判定を行います。
- **人狼全員脱落時のダミー破壊選択時間**: 破壊フェーズで人狼が全員脱落している場合、即スキップせず3〜10秒（サーバー側ランダム）のダミー選択時間を設け、通常の破壊フェーズと同じ表示のまま、終了時に「足場は破壊されませんでした」と表示して何も破壊しません。
- **強制終了後の復活防止**: 破壊フェーズからのアスレチック開始は遅延タイマーのハンドルを保持して管理し、ゲーム終了時に全ての遅延タイマーを破棄します。開始側にもフェーズガードがあるため、強制終了後にアスレチックへ復活することはありません。
- **配置制限**: スタート島・ゴール島のXZ範囲と重なり、足場の底面が島上面+2.2m（高さ3.2m）より低い配置はサーバーで禁止します（観覧車はゴンドラ最下点で判定）。クライアントのゴーストも赤くなり、その場で配置できません。島の上空を通る高所の配置は妨げません。
- **ゴール判定は着地を要求**: ゴール島の範囲内に加えて、島上面に接地している場合のみ勝利になります。上空をジャンプで横切っただけでは勝利になりません。
- **ルール設定のフェーズ制限**: `rule:set` はロビーと結果（再戦準備）フェーズでのみ受理します。試合中の変更は無視されます。
- **パンチ判定のラグ補償**: サーバーは各プレイヤーの直近位置履歴（600ms分）を保持し、パンチ判定は現在位置に加えて直近240ms以内の履歴位置でも判定します。判定範囲そのもの（1.35m・±60°）は広げていません。
- **サーバー時刻オフセットの平滑化**: クライアントは同期のたびの単純上書きをやめ、`timesync.js` の平滑化（1回あたり最大±20ms、1秒超の乖離時のみ±250ms）で取り込みます。動く足場（水平移動・観覧車・テレポ・竹輪）が遅延ばらつきで跳ぶのを抑えます。
- **カード再配分の偏り解消**: 再配分は受取順をシャッフルしてから配るため、余りが特定のプレイヤーに固定されません。
- **竹輪の発動記録の保持**: サーバーは竹輪の発動時刻を5.2秒で削除せず保持し続けます。発動・復活の判定はクライアント/サーバー双方が発動時刻からの純粋関数で行うため、タイミング差で「乗ったのに発動しない」窓がありません。
- **その他**: 試合開始時の色再割当てが既存アバターの色にも反映されるようになりました。再接続時も名前の重複解消（初回参加と同じ一意化）を適用します。投票/守護/破壊パネルは内容が変わらない限り再描画しないため、クリック途中の無効化やホバー強調の固着が起きません。投票の「直後にアスレチック」判定は投票解決時点で記録され、ダミー破壊で時間が空いても結果パネルの4秒短縮が維持されます。

## 実装上の簡略化メモ

- 細長の当たり判定はOBB（有向ボックス）判定です。プレイヤー座標を足場のローカル空間へ変換し、上面への着地・側面の接触をローカル軸で判定します（クライアント衝突とサーバー側のBOT・物理代行で同じ考え方・同じ回転行列を使用）。
- ゲームパッドはキーコンフィグでボタン割当（ジャンプ/パンチ/溜めジャンプ）とスティック入れ替えが可能です。スティック自体への任意機能の割当は未対応です。ボタン対応は Gamepad API の標準マッピング（0=×, 1=○, 2=□, 3=△）に統一しており、DualShock 4 が非標準の生並び（0=□, 1=×, 2=○）で届く環境でも、入力時に標準 index へ正規化するため物理ボタンと内部設定が一致します（`public/js/padmap.js`）。
- スティック軸は「静止位置（ニュートラル）の校正」をしてから使います。スティックのドリフトや非標準マッピングの軸割当で、触っていない軸が 0 でない値を返し続ける環境では、以前はアスレチックフェーズでのみ有効なカメラ経路（pollPad）が毎フレームその値を回転入力として書き込み続け、開始直後にピッチが上限 1.2 rad に張り付いて視点が足元に固定される不具合がありました（実ブラウザ計測で、静止オフセット 0.85 の軸を与えると発表・カウントダウン中に 0.32 → 1.2 へ張り付き、マウス入力でも戻せないことを再現して特定）。現在は、静止値を「値が安定してから確定する」方式（`padmap.js` の `createCalibrator`）で校正します。パッドを初めて見た直後のウィンドウでは、値が150ms安定したら静止値として採用します（初回観測の時点で既に現れている大きな静止オフセットも無効化されます）。最初は軸が未確定（全0）で、遅れて現れる現実的な大きさのオフセットも、安定した時点で採用し直されます。一度でも違う値が観測された軸や、確定後に現れた大きな値は、スティックを倒したままの状態と区別できないため静止値として採用しません。校正には `captureNeutral` / `centerAxes`（純粋関数）も併用します。
- スティック軸の並びもボタンと同じく正規化します。一部の非標準マッピング環境（Linux系ドライバ経由など）では、軸が `[LX, LY, RX, L2, R2, RY]` の順で届き、右スティックYが index 5、トリガー軸（静止時 -1）が index 3, 4 を占めます。この並びのまま index 3 を右スティックYとして読むと、校正導入後はトリガーの静止値 -1 が差し引かれて実効値が常時 0 になり、**右スティックの垂直視点だけが完全に効かなくなる**不具合がありました（実ブラウザ計測で再現：生 index 5 を倒してもピッチ Δ=0、水平の index 2 は正常）。現在は、トリガー2軸がそろって静止端（-0.9 以下）にあることを署名としてこの並びを検出（ラッチ式）し、軸を標準のスティック順 `[LX, LY, RX, RY]` に並べ替えてから使うため、どちらの環境でも右スティックで垂直視点が効きます（`padmap.js` の `isTriggerInterleaved` / `standardAxes`）。
- 校正は試合中も自動で回復します（ドリフト追従）。アスレチック中に軸の生値が小さな一定値（|値| ≤ 0.5）のまま2.5秒安定したら、それを新しい静止値として再校正するため、開始時にキャラやカメラが勝手に動き始めても、パッドを再接続しなくても数秒で止まります。大きく倒した入力（全速前進など）は大きさの条件で絶対に採用されず、微振動のある通常の保持は「±0.02以内で2.5秒不変」の条件を満たさないため誤発しません。パッド再接続時は、切断前に確定していた校正値を復元して開始し（初回ウィンドウの無条件採用はしません）、倒したまま再接続しても中毒しません。以前の「保留付き再校正（突入時・再接続時に取り直す）」方式は、この安定性ゲート方式に置き換えられました。
- 竹輪の落下・復活サイクルはサーバー時刻ベースで全クライアント同期しています。
- ゲーム開始時に参加者間でプレイヤーカラーが重複していた場合、重複した参加者の中からランダムに、未使用色へ割り当て直してから開始します。
- 視点のピッチ（上下）は、入力値の検証＋毎フレームの健全性チェック（NaN時は既定値へ復旧）に加え、(1) movementX/Y が片軸だけ0で返る環境向けに client 座標差分への軸ごとフォールバック、(2) 1イベント分の移動量の上限（±300px。ポインターロック取得直後のスパイク対策）、(3) ポインターロック取得/解除時に差分フォールバック用の前回座標をリセット、で対策しています。なお、以前あった「入力があるのにピッチが変化しない場合に既定値へ戻すウォッチドッグ」は、系統計測で誤発（見上げてから同じ高さへ戻す正常な往復操作を「変化していない」と誤判定し、操作途中でピッチを 0.32 へ跳ばす。残差 0.548 rad）が実測されたため廃止しました。カメラ位置はプレイヤー位置＋視点入力（yaw/pitch/距離）だけで決まり、足場や島による干渉（障害物での距離・高さの変更）はありません。カメラ高さが下限（y=0.4）に当たる見上げ帯域では、高さを凍結せず距離を縮める（プルイン）ため、視線ピッチは入力ピッチと全域で一致します（旧実装は高さクランプと注視点の0.3倍連動で視線が圧縮・逆行していました）。注視点はカメラ軌道の中心に統一しています。垂直方向の平滑化（smoothY）は酔い防止ON時は dt 基準の指数平滑（接地中14/s・空中5/s）、OFF時も段差を分散させるため速い平滑（30/s）を常時かけています。リスポーン等のテレポート時は smoothY も現在位置へ同期し、カメラが旧高さから追いつく「すくい上げ」は起きません（旧実装ではリスポーン時点で最大 5.35m のずれを実測）。
- 足場の支持対象（追従する足場）は「そのフレームで接触した中で最も高い上面」を1つだけ選ぶ方式です。重なった足場が処理順に支持を上書きしていた旧方式では、移動足場同士のすれ違い等で追従中心が入れ替わり、足場にめり込んで沈んでから上面へポップする動き（実測: 沈下0.75m→1.035mのポップ）が発生していました。生存者同士の押し合い補正にも1フレーム上限（12m/s）を設け、相手位置の階段状の配信（100ms周期）でカメラが跳ばないようにしています。
- マウス視点操作（FPSスタイル）を ON にすると、アスレチックフェーズでは右ドラッグなしでマウス移動だけで視点が回転します。ポインターロックはフェーズ開始時とキャンバスクリック時に取得を試みますが、回転はロックの成否に依存せず、未ロック時は movementX/Y（または client 座標差分）で回転します。ロック取得に失敗した環境では、以後のクリックは通常のパンチとして扱われます。ロック取得のためのクリックではパンチしません。
- キャラクターの初期配置はスタート島の上面（y=1）に足裏が接地した状態です（スポーン位置・2戦目以降のリセット・リスポーン共通）。
- 観戦者（試合不参加の途中入室者）は、アスレチック中「常時ゴースト」のキャラクターとして本人視点では半透明で表示され、自分で操作して移動できます。落下するとゴーストのままスタート島へリスポーンします。生存者からは見えず、ゴースト同士では見えます。観戦者は押し合い・パンチ・竹輪トリガー・ゴール/勝敗判定の対象外で、リザルトにも表示されません。
- パンチはキーコンフィグで Mouse0 以外のキー/ボタンに割り当てても発火します（立ち上がりエッジ検出）。クールダウン（420ms）はモーション中のみで、カウントダウン終了後とモーション完了後は確実に発火します。ポインターロック取得のためのクリックではパンチしません。
- 竹輪の選択判定には、側面の開口部を覆う透明なヒットプロキシを使っています（見た目と当たり判定の全面性はサーバー側も共通です）。
